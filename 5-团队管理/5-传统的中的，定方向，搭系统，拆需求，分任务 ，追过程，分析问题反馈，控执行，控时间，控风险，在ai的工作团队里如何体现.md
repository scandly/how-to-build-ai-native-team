传统管理动作在Vibe Coding团队中的新生（概要版）

**核心转变**：以前花80%时间做的事（盯执行、催进度），现在只需20%；以前花20%时间做的事（拆逻辑、定边界、建知识库），现在要花80%。

---

### 七大管理动作的质变
| 维度 | 放（不再死控） | 收（死死盯住） |
|:---|:---|:---|
| 代码怎么写 | 完全交给AI+员工 | - |
| 用几天写 | 不排期，以业务验证为节点 | - |
| 谁写哪部分 | 不按工种分，按闭环分 | - |
| 业务意图对齐 | - | 统筹者亲自盯 |
| 边界条件验收 | - | 防御性测试覆盖是硬指标 |
| 知识库沉淀 | - | 每个踩坑必须转为RAG资产 |
| 自动化风控 | - | 拦截规则覆盖所有致命场景 |

### 各动作变化要点
- **定方向**：AI不会质疑方向，只会高效执行错误方向，方向定错容错率为零
- **搭系统**：从搭组织架构→搭AI知识工具基座（RAG+代码规范Agent+CI/CD）
- **拆需求**：不拆页面/接口，拆"业务逻辑约束"和"防御性测试用例"
- **分任务**：AI可全栈生成，按业务闭环分（一人用AI端到端交付）
- **追过程**：不追进度，追"AI是不是理解错意图跑偏了"
- **分析问题**：不追责人，复盘Prompt哪里缺约束+RAG缺了什么
- **控风险**：人根本追不上AI速度，用系统对抗系统（AI Code Review Agent自动拦截）
